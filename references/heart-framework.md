# HEART 框架完整指南

> 基于 Chapman & Rodden《Quantitative User Experience Research》(2023)

---

## HEART 框架概述

HEART 是 Google 提出的用户体验指标框架，涵盖五个维度：

| 维度 | 含义 | 典型指标 |
|------|------|----------|
| **H**appiness | 用户满意度 | NPS, SUS, CSAT, 情感评分 |
| **E**ngagement | 用户参与度 | 使用频率、会话时长、功能使用率 |
| **A**doption | 新用户获取 | 新功能采用率、注册转化率、首次使用率 |
| **R**etention | 用户留存 | 7/30/90日留存率、流失率、复购率 |
| **T**ask Success | 任务完成率 | 完成率、错误率、任务时间、成功率 |

---

## Goals-Signals-Metrics (GSM) 工作流

### 第一步：定义 Goals（目标）

目标必须是**具体的、可衡量的**，而非模糊的"提升体验"。

**差的 Goal：** "提升用户满意度"
**好的 Goal：** "将新用户首周留存率从 35% 提升至 50%"

### 第二步：定义 Signals（信号）

信号是目标的**行为指示器**，回答"我们如何知道目标在改善？"

| Goal | Signal |
|------|--------|
| 提升新用户留存 | 7日内完成核心行为的用户比例 |
| 提升功能采用率 | 功能曝光后7日内使用的用户比例 |
| 降低任务错误率 | 任务完成过程中的错误次数 |

### 第三步：定义 Metrics（指标）

指标是信号的**具体测量方式**，回答"我们如何量化信号？"

| Signal | Metric | 数据来源 |
|--------|--------|----------|
| 7日内完成核心行为 | 7日留存率 (%) | 事件日志 |
| 功能曝光后7日内使用 | 采用率 (%) | 埋点数据 |
| 任务完成过程中的错误次数 | 平均错误次数/任务 | 用户测试/日志 |

## 各维度详细指标库

### Happiness（满意度）

| 指标 | 测量方法 | 适用场景 |
|------|----------|----------|
| NPS (Net Promoter Score) | 0-10 分推荐意愿 | 整体满意度追踪 |
| SUS (System Usability Scale) | 10 题李克特量表 | 可用性评估 |
| CSAT (Customer Satisfaction) | 1-5 分满意度评分 | 单次交互后评估 |
| 情感评分 | 面部表情/自报告情感 | 体验情感分析 |

### Engagement（参与度）

| 指标 | 测量方法 | 适用场景 |
|------|----------|----------|
| DAU/MAU | 日活/月活用户数 | 整体活跃度 |
| 会话时长 | 平均每次使用时长 | 内容类产品 |
| 功能使用率 | 各功能使用用户占比 | 功能价值评估 |
| 使用频率 | 每周/月使用次数 | 产品粘性评估 |

### Adoption（采用率）

| 指标 | 测量方法 | 适用场景 |
|------|----------|----------|
| 新功能采用率 | 曝光后使用人数/曝光人数 | 新功能发布 |
| 注册转化率 | 注册完成数/访问数 | 获客漏斗 |
| 首次使用完成率 | 完成首次核心行为比例 | 新用户引导 |
| 功能发现率 | 发现功能的用户占比 | 功能可见性 |

### Retention（留存率）

| 指标 | 测量方法 | 适用场景 |
|------|----------|----------|
| 7日留存率 | 第7日回访用户/新用户 | 短期留存 |
| 30日留存率 | 第30日回访用户/新用户 | 中期留存 |
| 90日留存率 | 第90日回访用户/新用户 | 长期留存 |
|  cohort 留存 | 同期群留存曲线 | 趋势分析 |

### Task Success（任务成功）

| 指标 | 测量方法 | 适用场景 |
|------|----------|----------|
| 完成率 | 成功完成任务比例 | 核心流程 |
| 错误率 | 任务中错误次数/总任务数 | 可用性 |
| 任务时间 | 完成任务平均时长 | 效率评估 |
| 求助率 | 需要帮助的比例 | 易用性 |

## HEART 仪表盘设计

### 仪表盘层级

```
Level 1: Executive Dashboard (HEART 总分)
  ↓
Level 2: Dimension Dashboard (各维度趋势)
  ↓
Level 3: Metric Detail (具体指标钻取)
  ↓
Level 4: Raw Data (原始数据/日志)
```

### 仪表盘最佳实践

1. **每个维度 1-3 个核心指标**，不超过 15 个总指标
2. **趋势线 > 快照数字**，展示 30/90 天趋势
3. **基准线**，标注行业基准或历史最佳
4. **颜色编码**，红/黄/绿三色状态指示
5. **下钻能力**，从 HEART 总分到具体指标

## 实战案例：电商 App HEART 框架

### Goal 定义

| HEART 维度 | Goal |
|------------|------|
| Happiness | NPS ≥ 50, SUS ≥ 70 |
| Engagement | 周活跃天数 ≥ 3 天的用户占比 ≥ 40% |
| Adoption | 新功能（智能推荐）7日采用率 ≥ 30% |
| Retention | 30日留存率从 25% 提升至 35% |
| Task Success | 下单完成率 ≥ 85%，平均下单时间 < 3 分钟 |

### GSM 映射

| Goal | Signal | Metric |
|------|--------|--------|
| NPS ≥ 50 | 用户推荐意愿 | NPS 分数（月度调研） |
| SUS ≥ 70 | 用户感知可用性 | SUS 得分（季度测试） |
| 周活跃 ≥ 3 天 | 用户回访频率 | DAU/MAU + 周活跃天数分布 |
| 智能推荐采用率 ≥ 30% | 推荐功能使用 | 推荐曝光→点击→加购转化率 |
| 30日留存 ≥ 35% | 新用户回访 | Cohort 30日留存率 |
| 下单完成率 ≥ 85% | 流程完成 | 购物车→支付成功转化率 |

## 常见陷阱

1. **指标过多** — HEART 不是收集所有数据，而是选择最相关的 5-15 个指标
2. **只收集不行动** — 指标必须有对应的行动阈值（如 NPS < 40 触发调查）
3. **忽略样本量** — 小样本的指标波动可能是噪声而非信号
4. **忽略基线** — 没有基线的指标无法判断改善或恶化
5. **混淆相关和因果** — 指标变化可能有多种原因，需要实验验证

## 🔗 跨技能协作 (Cross-Skill Collaboration)

HEART 框架是定量验证的核心工具，为其他技能的数据驱动决策提供指标支撑：

| 技能 | 协同方式 |
|------|----------|
| [🔍 Universal Design Methods](https://github.com/AliDujie/universal-design-methods) | UDM 定性发现 → HEART 指标定义 |
| [🎯 JTBD Knowledge](https://github.com/AliDujie/jtbd-knowledge-skill) | JTBD 机会优先级 → HEART 指标权重调整 |
| [💎 Value Proposition Design](https://github.com/AliDujie/value-proposition-design) | VPD 假设 → HEART 指标跟踪验证 |
| [📈 Storytelling with Data](https://github.com/AliDujie/storytelling-with-data) | HEART 仪表盘数据 → SWD 高管汇报可视化 |

> 💡 **推荐工作流**: `UDM (定性发现) → HEART (指标定义) → 持续监控 → SWD (数据叙事)`

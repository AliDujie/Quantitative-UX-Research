## 研究规划方法论 / Research Planning Methodology

### 反向工作法 (Reverse Working)

QuantUX 推荐**反向工作法**规划研究：先定义决策需要什么证据，再设计收集证据的方法。

```
业务决策 → 需要什么证据 → 什么研究能产生证据 → 研究设计 → 执行
Decision ← Evidence ← Method ← Design ← Execution
```

**步骤**：

1. **定义决策** — 研究结束后，利益相关者要做出什么决策？
2. **定义证据** — 什么数据能支持或反对这个决策？
3. **选择方法** — 哪种研究方法能产生所需证据？
4. **设计方案** — 样本量、时间线、资源估算
5. **模拟预览** — 用模拟数据确认研究设计的可行性

### 研究类型矩阵

| 研究目标 | 推荐方法 | 样本量参考 | 时间估算 |
|---------|---------|-----------|---------|
| 探索性：理解问题空间 | 日志分析 + CSat 基线 | 现有用户全量 | 1-2 周 |
| 描述性：衡量当前体验 | HEART 框架 + CSat | N≥384 (95% CI, ±5%) | 2-3 周 |
| 因果性：验证改动效果 | A/B 测试 | 基于 MDE 计算 | 3-6 周 |
| 优先级：功能排序 | MaxDiff | N≥200 | 1-2 周 |
| 趋势：跟踪体验变化 | 纵向 CSat + HEART 刷新 | 季度追踪 | 持续 |

## 请求诊断框架 / Request Diagnosis Framework

当利益相关者提出研究请求时，先诊断真实需求，再推荐最佳方法。

### 诊断维度

| 维度 | 问题 | 输出 |
|------|------|------|
| 决策类型 | 要做什么决策？(Go/No-go, 优先级, 方向) | 决策分类 |
| 时间敏感性 | 决策截止日期？ | 时间约束 |
| 现有数据 | 有什么数据可用？ | 数据资产清单 |
| 资源约束 | 预算/人力/工具限制？ | 资源边界 |
| 利益相关者 | 谁需要看结果？ | 受众分析 |

### 诊断流程 (QuantUX `diagnose_request`)

```python
from quantux import QuantUXSkill
skill = QuantUXSkill("你的产品")

# 输入利益相关者请求，自动诊断
diagnosis = skill.diagnose_request("我们想知道新设计是否更好")
# → 输出：推荐的技能组合、样本量估算、时间线、风险
```

### 常见请求模式与推荐

| 利益相关者请求 | 真实需求 | 推荐方法组合 |
|---------------|---------|-------------|
| "用户喜欢我们的新产品吗？" | 满意度测量 | CSat 调查 + HEART Happiness 维度 |
| "新版本比旧版本好吗？" | 因果验证 | A/B 测试 (先算样本量) |
| "应该先做哪个功能？" | 优先级排序 | MaxDiff 强制选择 |
| "用户在使用产品时卡在哪？" | 行为路径分析 | 日志序列分析 + 漏斗转化 |
| "整体体验健康度如何？" | 全局诊断 | HEART 框架完整评估 |
| "投资 UX 的 ROI 是多少？" | 业务影响评估 | CEO 决策支持模块 |

## 研究方案设计 / Research Design

### 方案模板

每个研究方案应包含：

1. **研究问题** — 具体、可操作、与决策直接关联
2. **假设** — 可被数据证伪的陈述
3. **方法** — 具体研究方法 + 理由
4. **样本量** — 基于统计功效计算
5. **时间线** — 准备 → 收集 → 分析 → 汇报
6. **资源** — 人力、工具、激励成本
7. **风险** — 潜在偏差 + 缓解措施
8. **交付物** — 报告格式 + 受众

### 样本量快速参考

| 场景 | 基线 | MDE | 推荐样本量/组 |
|------|------|-----|-------------|
| 转化率优化 | 35% | 3% | ~2,000 |
| 转化率优化 | 35% | 5% | ~700 |
| UX 任务完成率 | 70% | 10% | ~200 |
| CSat 均值检测 | — | 0.3 SD | ~175 |
| MaxDiff 偏好 | — | — | 200-500 |

## 模拟结果预览 / Simulated Results Preview

反向工作法的核心：在执行前，用模拟数据确认研究设计能产生有用的结果。

### 模拟预览流程

```python
from quantux import QuantUXSkill
skill = QuantUXSkill("旅行平台")

# 生成模拟报告，确认研究设计
report = skill.generate_report("Q1 用户满意度研究 (模拟)", include_ceo_analysis=True)

# 利益相关者预览：
# - 报告格式是否符合决策需要？
# - 业务影响估算是否有说服力？
# - 时间线和资源投入是否可接受？
```

### 预览检查点

- [ ] 报告中的数据是否能支持/反对预期决策？
- [ ] 置信区间宽度是否足够做决策？
- [ ] 业务影响估算是否覆盖了关键场景？
- [ ] 时间线是否匹配决策截止日期？
- [ ] 资源投入与预期收益是否匹配？

## 利益相关者管理 / Stakeholder Management

### 利益相关者映射

| 角色 | 关注点 | 汇报重点 |
|------|--------|---------|
| CEO/高管 | ROI、业务影响、资源分配 | 业务影响模块 + 资源估算 |
| 产品 VP | 功能优先级、路线图影响 | MaxDiff 结果 + A/B 测试结论 |
| 设计负责人 | 体验指标、可用性改进 | HEART 框架 + CSat 趋势 |
| 工程师 | 技术指标、实验实现 | 日志分析 + A/B 测试设计 |
| 项目经理 | 时间线、资源、里程碑 | 验证时间线 + 资源估算 |

### 沟通节奏

| 阶段 | 沟通内容 | 受众 |
|------|---------|------|
| 立项前 | 模拟结果预览 + 资源估算 | 决策者 |
| 每周 | 进度更新 + 风险预警 | 核心团队 |
| 完成后 | 完整报告 + 业务影响 | 全体利益相关者 |
| 追踪期 | 趋势对比 + 行动效果 | 持续受众 |

## 研究规划检查清单 / Research Planning Checklist

### 研究启动前

- [ ] 研究问题已定义且与业务决策直接关联
- [ ] 假设可被数据证伪
- [ ] 样本量已基于统计功效计算
- [ ] 时间线与决策截止日期匹配
- [ ] 资源估算已获批准
- [ ] 模拟报告已生成并获利益相关者确认

### 研究执行中

- [ ] 数据收集按计划进行
- [ ] 偏差和异常已记录
- [ ] 中期检查不干扰研究设计（避免 p-hacking）
- [ ] 利益相关者定期更新

### 研究完成后

- [ ] 分析报告完整（含 CEO 模块如需）
- [ ] 结果已转化为具体行动建议
- [ ] 决策已基于研究结果做出
- [ ] 经验教训已归档

## 与其他能力的协作

研究规划（能力 6）是 QuantUX 的**前置协调层**：

```
研究规划 (能力6)
    ├── 诊断请求 → 推荐方法组合
    ├── 设计方案 → 调用 HEART/A-B/MaxDiff/CSat/日志 (能力1-5)
    └── 生成报告 → 研究报告 (能力7)
```

**与生态系统的协作**：

- **UDM → 研究规划**: UDM 的定性发现为研究规划提供假设来源
- **JTBD → 研究规划**: JTBD 的机会评分帮助确定研究优先级
- **STM → 研究规划**: STM 的战略框架帮助对齐研究问题与业务目标

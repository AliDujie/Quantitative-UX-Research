# 量化用户体验研究 (Quant UX Research) 执行技能

基于 Chapman & Rodden《Quantitative User Experience Research: Informing Product Decisions by Understanding Users at Scale》(Apress 2023) 构建。本Skill不仅提供理论指导，更具备直接执行能力——可以实施HEART框架工作坊、设计CSat问卷、分析用户行为路径、执行MaxDiff优先级排序、设计A/B测试、规划研究项目、生成研究报告。

## 核心理论速览

**Quant UXR定义**：运用实证研究方法，在规模化场景下为以用户为中心的产品设计提供信息支持。

**T型技能模型**：Quant UXR需要 编程 ∩ UX研究 ∩ 统计 三个领域的交叉能力。

**以用户为中心五原则**：
1. 采纳用户视角，从用户角度考虑问题
2. 评估用户中心变量和结果
3. 用认知方法回答"为什么"
4. 聚焦未满足需求而非假设性利益
5. 关联UX行动和利益相关者

**产品生命周期研究映射**：
- 规划阶段 → 日志分析、MaxDiff、调查、聚类
- 早期开发 → 联合分析、MaxDiff
- 后期开发 → A/B测试、可用性测试
- 发布后 → CSat、日志分析、体验采样

## 执行能力一：实施HEART框架与指标体系

当用户需要定义产品UX指标、建立度量体系、或召开指标工作坊时，按以下流程执行：

### 输入要求
向用户收集：产品/服务名称、当前产品阶段、团队角色组成、已有的指标（可选）

### 执行步骤

**第一步：介绍HEART五维度**
- **H**appiness（愉悦）：用户态度——满意度、感知易用性、NPS
- **E**ngagement（参与）：用户参与深度——频率、强度、交互深度
- **A**doption（采纳）：新用户/新功能采纳情况
- **R**etention（留存）：用户持续使用情况
- **T**ask Success（任务成功）：任务完成效率和效果

**第二步：引导Goals-Signals-Metrics流程**
1. 团队协作定义目标(Goals)——以用户体验为中心，不需要覆盖所有HEART类别
2. 为每个目标识别信号(Signals)——可观察的用户行为/态度，同时考虑成功和失败信号
3. 将信号转化为指标(Metrics)——优先使用比率/百分比，确定数据来源

**第三步：输出指标体系**
输出完整的GSM映射表和实施建议，包含：核心指标清单、数据来源、优先级排序。

**第四步：提醒常见陷阱**
- Goodhart法则：当度量成为目标，就不再是好的度量
- 参与度指标可能鼓励成瘾性使用（伦理考量）
- 从一个团队和一个项目开始，不要一次覆盖太多

### 输出格式
输出完整的HEART指标体系文档，包含：GSM映射表、核心指标定义、数据来源、工作坊执行指南。

## 执行能力二：CSat调查设计与分析

当用户需要做满意度调查、客户反馈收集时，按以下流程执行：

### 输入要求
向用户收集：产品名称、调查方式（邮件/面板/产品内）、目标人群、调查频率

### 执行步骤

**第一步：设计调查问卷**
遵循极简原则，核心只需：
- 1-2个满意度评分题（5点或7点量表）
- 1个开放式问题（最有价值的定性数据来源）
- 可选：人口统计/行为信息（用于评估样本代表性）

**第二步：选择调查机制**
| 方式 | 优势 | 劣势 |
|------|------|------|
| 邮件调查 | 可确认真实用户，可关联账户信息 | 非盲测，邮件过滤 |
| 第三方面板 | 灵活，可触达新客户，可做盲测 | 不知谁是真实客户 |
| 产品内调查 | 即时触达，上下文清晰 | 仅触达活跃用户 |

**第三步：分析数据**
1. 计算Top-2-Box得分（顶部两个评分的比例）
2. 计算二项式置信区间
3. 跟踪时间趋势（在同一群体内比较，不跨群体比较绝对值）
4. 检查Simpson悖论（分组后趋势可能反转）

**第四步：生成报告**
包含：样本元数据、评分分布图、时间趋势、置信区间、关键发现、闭环反馈(CTL)建议。

### 输出格式
输出完整的CSat问卷文档或分析报告。

## 执行能力三：日志序列路径分析

当用户需要分析用户行为路径、理解用户旅程时，按以下流程执行：

### 输入要求
向用户收集：日志数据格式、关注的事件类型、会话间隔阈值（默认15分钟）、分析目标

### 执行步骤

**第一步：数据准备**
- 按用户和时间戳排序
- 基于时间间隔划分会话
- 过滤关注的事件类型

**第二步：序列构建与频率统计**
- 将每个会话的事件拼接为序列字符串
- 限制最大序列长度（如5步）
- 统计每个唯一序列的出现频率

**第三步：可视化与分析**
- 准备Sunburst图数据（内环=第一步行为，每个后续环=下一步）
- 构建Markov转移概率矩阵
- 识别常见起始页面和放弃点

**第四步：输出分析报告**
包含：数据概览、Top路径、常见起始页面、转移矩阵、放弃点分析、后续研究建议。

### 后续分析方向
- 页面分类归并（将URL归为高层类别）
- 结合定性研究（针对特定路径的可用性测试）
- 用户拦截调查（在特定页面收集满意度）

## 执行能力四：MaxDiff功能优先级排序

当用户需要对功能需求排优先级、评估用户偏好时，按以下流程执行：

### 输入要求
向用户收集：研究目的、待排序的项目列表（至少10个）、目标样本量

### 执行步骤

**第一步：设计调查**
- 设计问题头部："考虑以下项目，选择对您最重要和最不重要的一个"
- 项目设计原则：短（几个词）、单一概念、适合互相权衡
- 计算屏幕数：s = K × T / M（K=项目总数，T=每项出现次数3-5，M=每屏项目数3-7）

**第二步：验证设计**
- 检查项目数量（≥10，≤35）
- 验证项目文本长度
- 检查所有项目对之间的权衡合理性

**第三步：分析数据**
- 计数分析：差异分数 = 被选为最重要次数 - 被选为最不重要次数
- 标准化差异分数（范围-1到1）
- 排序输出优先级表格

**第四步：输出结果**
排序后的优先级表格，包含：排名、项目、最重要次数、最不重要次数、差异分数、标准化分数。

### 样本量建议
- N=200：样本级结果通常稳定
- N=1000：支持分群分析
- N=100/组：已知分组时的目标

## 执行能力五：A/B测试设计与分析

当用户需要做A/B实验、对比方案效果时，按以下流程执行：

### 输入要求
向用户收集：实验假设、用户定义、主要指标、护栏指标、基线转化率、最小可检测效应

### 执行步骤

**第一步：实验设计**
1. 明确"用户"定义（人/设备/账户/客户）
2. 确定主要结果指标（确保衡量UX改善而非仅业务指标）
3. 设定护栏指标（监测负面影响）
4. 识别混淆变量

**第二步：样本量计算**
使用公式：n = (z_α + z_β)² × 2p(1-p) / MDE²
- 默认α=0.05, power=0.8

**第三步：结果分析**
1. 计算转化率差异和置信区间
2. 聚焦实际效应大小而非统计显著性
3. 检查护栏指标
4. 提供业务解读

**第四步：输出报告**
包含：对照组vs实验组数据表、差异分析、置信区间、业务解读建议。

### 关键提醒
- **最重要的方面是实验设计，而非统计分析本身**
- 避免过度优化单一指标
- 准备定性研究补充（理解"为什么"）

## 执行能力六：研究规划与利益相关者诊断

当用户需要规划研究项目、评估研究请求时，按以下流程执行：

### 输入要求
向用户收集：利益相关者的原始问题/请求、产品名称、产品阶段

### 执行步骤

**第一步：诊断利益相关者请求**
用六个诊断问题逐一评估：
1. 是否以用户为中心？→ 否则帮助重新框定
2. 会影响什么决策？→ 不明确则要求澄清
3. 需要什么精确度？→ 方向性or精确
4. 已有什么数据？→ 有则先做EDA
5. 时间和资源约束？→ 紧急则快速分析
6. 机会成本？→ 做这个意味着不做什么

**第二步：推荐研究方法**
根据问题类型和产品阶段，从以下方法中推荐：
- 调查(Survey)、日志分析、A/B测试、MaxDiff、联合分析、CSat、体验采样、可用性测试

**第三步：反向工作**
先展示模拟结果预览，确认有价值再投入。

**第四步：输出研究计划**
包含：研究问题、方法、数据来源、时间线、抽样策略、交付物预览。

### 常见问题应对

| 问题 | 应对策略 |
|------|----------|
| 验证性研究("验证我们的方向") | 转化为具体的用户中心问题 |
| 统计显著性误解 | 用置信区间和实际效应替代 |
| 挑拣结果(Cherry Picking) | 提前明确问题和决策标准 |
| 仅负面时质疑(COIN) | 使用多方法、提前获取支持 |

## 执行能力七：研究报告生成

当用户需要撰写研究报告、整理研究发现时，按以下流程执行：

### 输入要求
向用户收集：研究标题、执行摘要、研究问题、方法、发现、建议

### 执行步骤

**第一步：按标准结构组织**
1. 执行摘要（1段或1页幻灯片）
2. 研究问题（利益相关者原始问题 + 转化后的研究问题）
3. 方法概述（简述，不含技术细节）
4. 关键发现（每个配清晰图表，含置信区间）
5. 建议（具体可行的行动建议）
6. 附录（技术细节、代码链接）

**第二步：应用四大交付物原则**
1. **简短聚焦行动**：执行摘要+关键问题和答案
2. **最少技术细节**：不含方程/模型输出/显著性解释
3. **保持无偏**：如实传达发现，包括坏消息
4. **可复现可推广**：脚本化分析，评估结果可靠性

**第三步：输出报告**
生成完整的Markdown格式研究报告。

## Python 工具包

Skill 提供完整的 Python API，位于 `quantux/` 包目录下，可直接导入使用。

### 核心模块

| 模块 | 类/函数 | 用途 |
|------|---------|------|
| `config.py` | `AnalysisConfig` | 运行时配置：HEART维度、输出格式、置信水平 |
| `utils.py` | `load_knowledge`, `search_knowledge` | 知识库加载与搜索，统计工具函数 |
| `templates.py` | 模板常量 | 工作坊模板、调查模板、报告模板、诊断问题 |
| `heart.py` | `HEARTBuilder` | HEART框架：GSM定义、指标体系构建、工作坊指南 |
| `csat.py` | `CSatSurveyBuilder`, `CSatAnalyzer` | CSat调查：问卷设计、Top-2-Box分析、趋势报告 |
| `logs.py` | `LogsAnalyzer` | 日志分析：会话化、序列频率、Markov矩阵、Sunburst数据 |
| `maxdiff.py` | `MaxDiffDesigner`, `MaxDiffAnalyzer` | MaxDiff：调查设计、计数分析、优先级排序 |
| `abtest.py` | `ABTestPlanner`, `ABTestAnalyzer` | A/B测试：样本量计算、差异分析、结果解读 |
| `research.py` | `ResearchPlanner`, `ReportBuilder` | 研究规划：请求诊断、方法推荐、报告生成 |

### 使用示例

```python
import sys
sys.path.insert(0, "/path/to/quant-ux-skill")
from quantux import QuantUXSkill

skill = QuantUXSkill("飞猪旅行")

# 能力1: HEART框架
skill.heart_builder.add_goal("happiness", "提升用户对预订流程的满意度")
skill.heart_builder.add_signal("提升用户对预订流程的满意度", "预订后满意度评分", "success")
skill.heart_builder.add_metric("预订后满意度评分", "预订满意度T2B", "Top-2-Box比例", "survey", True)
print(skill.build_heart_framework())

# 能力2: CSat分析
skill.csat_analyzer.add_data_point("2024Q1", 500, {1:10, 2:20, 3:50, 4:180, 5:240})
skill.csat_analyzer.add_data_point("2024Q2", 480, {1:8, 2:18, 3:45, 4:190, 5:219})
print(skill.csat_analyzer.generate_report())

# 能力3: 日志分析
skill.logs_analyzer.add_event("u1", "2024-01-01 10:00:00", "首页")
skill.logs_analyzer.add_event("u1", "2024-01-01 10:02:00", "搜索")
skill.logs_analyzer.add_event("u1", "2024-01-01 10:05:00", "详情页")
print(skill.analyze_logs())

# 能力4: MaxDiff
print(skill.design_maxdiff("功能优先级", ["快速搜索", "价格对比", "评价可信", "退款便捷"]))

# 能力5: A/B测试
n = skill.calculate_ab_sample_size(0.35, 0.03)
print(f"每组需要 {n} 个样本")
print(skill.analyze_ab_test("对照组", 5000, 1750, "实验组", 5000, 1900))

# 能力6: 研究规划
print(skill.diagnose_request("验证我们的新设计方向是否正确"))

# 知识库搜索
results = skill.search_knowledge("置信区间")
```
